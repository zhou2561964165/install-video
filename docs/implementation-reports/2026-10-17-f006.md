# F-006：游客首页与按需登录入口

状态：实现与验证完成，等待用户查验。独立复核提出的恢复失败提示问题已修复，并以RED→GREEN回归和浏览器复现确认修复。

## 确认范围

- 未登录及认证恢复中显示首页；顶部登录按钮显式打开登录/注册页。
- 首页可以填写视频URL。匿名提交解析只在首页提示请使用顶部登录按钮，不发送解析或其他业务API。
- 登录/注册页可返回首页并保留URL；登录/注册成功返回首页并保留URL，但不自动解析。
- 启动时token恢复成功直接进入首页并显示AuthBar；恢复失败回游客首页。
- 注销或切换账号仍清除会话业务状态；后端Bearer/JWT鉴权、额度和接口权限保持不变。
- 复用现有React、`useAuth`及`AuthScene`，不新增框架或依赖；不修改环境配置或模型文件。
- Live2D仍仅在已认证、非手机UA且视口宽度大于800px时初始化；F-003已查验行为保持。

## 实施状态

前端实现涉及[App.jsx](../../frontend/src/App.jsx)、[AuthScene.jsx](../../frontend/src/components/AuthScene.jsx)、[EntryScene.jsx](../../frontend/src/components/EntryScene.jsx)及对应的[App.test.jsx](../../frontend/src/App.test.jsx)、[AuthScene.test.jsx](../../frontend/src/components/AuthScene.test.jsx)；样式使用[reference.css](../../frontend/src/styles/reference.css)和[tokens.css](../../frontend/src/styles/tokens.css)，未增加依赖或路由框架。独立审查发现`useAuth`现有额度刷新存在迟到响应风险：`getMe`可能在退出或切换账号后写入旧会话额度。本轮没有修改该hook，也没有扩大F-006范围；该新发现登记为未排期H-010，见[总表](../follow-up-plan.md#31-历史候选统一归档均未排期)。
