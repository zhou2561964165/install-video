用户在上一轮交付后授权继续建议步骤；多 agent 的模型和推理沿用主 agent。本轮从 `47a1ad8` 开始，上一轮证据保持原样。

## 工程约定

UI、视觉与交互先用 `ui-ux-pro-max` 和 `design-system`；技能优先于计划，样式走 primitive → semantic → component 三层 token。能力与阈值配置化，避免大规模重构。`ytdlp_service.py` 是唯一接触 yt-dlp 的层，字幕与 LLM 通过窄接口，视觉只读 scene，不修改下载状态。用户配置、数据库与模型资产保持原样。

## 目标与实施顺序

1. 获取许可明确的真实中英文字幕，尽可能覆盖短、中、长内容；保留来源、许可、原件和文本哈希。来源 agent 在看到模型输出前固定重要事实、数字、条件、末尾结论和禁止虚构内容。不人工扩写来制造长样本。
2. 使用当前配置模型做基线评测，再针对测到的冗余或事实缺陷做最小修复，使用相同语料对照。所有分段与合并 HTTP POST 都计入独立持久化预算，最多24次，无自动 POST 重试，原12次台账不变。没有测到缺陷时保留生产代码。
3. 验证许可明确的公网样本在375px页面解析、服务器下载、浏览器保存，再用 ffprobe 校验。独立运行启用 WebGL 的浏览器，记录渲染器、纹理限制、Live2D 资源与初始化、实际画面及错误。软件渲染和 headless 视口不描述为物理手机 GPU 兼容。
4. 根 agent 对源文件、事实与结果独立复核，完成适当回归和构建，先提交实现再提交文档，停止自己的测试服务，报告下一项建议并等待用户指示。

## 分工与边界

来源 agent 只维护新质量目录的 corpus、采集脚本与来源报告。质量 agent 维护同目录的评测脚本、结果和报告，以及必要的 `llm_service.py` 与测试。浏览器 agent 只维护新的公网移动/GPU证据目录，发现产品缺陷后先协调文件归属。根 agent 维护共享计划、主文档与提交；另行安排独立复审。

使用隔离数据库和临时下载目录，不更改 `backend/jobs.db`、`.env`、用户 `AGENTS.md` 或旧 raw 目录权限。新截图和结果不覆盖旧证据；报告不含密钥、cookies或带凭据的地址。不增加支付、ASR、SSE或新UI功能。

## 验收标准

- 真实语料可追溯，预期事实在调用前冻结，评测输入与提示词有哈希，输出与实际请求台账可核对。
- 数字、条件、末尾结论和语义重复按固定事实逐项评审；有限样本不推广为所有字幕准确率，自动转写错误与模型错误分开。
- 公网手机视口有真实保存产物证据；GPU能力、实际渲染和降级结果分别说明，访问失败保留原始错误。
- 生产变更有相关测试，无提示词字符串镜像测试；最终测试、构建、独立复审和交接如实记录。
