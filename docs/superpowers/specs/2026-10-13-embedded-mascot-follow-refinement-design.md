## 3. 角色嵌入的布局与行为

### 3.1 页面中的角色区域

| 页面/宽度 | 推荐布局 | 内容与交互要求 |
| --- | --- | --- |
| 入口宽屏，建议≥1180px | 主标题、解析框和示例网站为主内容列，角色放相邻的独立展示列 | 不与主标题、输入、解析按钮、网站按钮和顶部导航重叠 |
| 入口中窄屏 | 主内容单列，角色在示例网站下面占文档流区域 | 缩窄后自然换行/堆叠，不能漂浮到表单上 |
| 已解析的视频工作台 | 复用现有内容之后的角色区域，位于双栏工作区下方 | 保留封面、格式、下载和AI内容面板宽度，不增加挤压内容的第三列 |
| 解析中/状态切换 | 沿用当时页面的预留区域；无有效区域时暂时隐藏角色 | 不在几何尚未就绪时回退到视口中央漂浮 |

入口宽屏候选区域为宽220–300 CSS px、高240–360 CSS px；窄屏候选宽不超过340px、高约220px。这些尺度必须转为token并随版面核对，不能在多个组件散写像素。区域融入既有背景与留白，不额外新增“角色”标题、浮动按钮或装饰边框。

角色尺寸以区域可用宽高的contain上界计算，默认完整可见。现有“变大/变小”仍可用，但不突破区域容量；不能沿用视口高度×倍率把角色放大到覆盖正文。加载失败/纹理能力不足沿用现有降级，空区域可收起；不新增模型资源。

### 3.2 拖动、滚动与菜单

- 默认后续模式为`embedded`：显示、拖动与点击热区共同受角色区域约束。保留点击/Enter/Space换装和键盘焦点。
- 拖动只在区域内调整，不越出区域覆盖其他组件；尺寸和区域变化后重新约束，场景切换或失去指针捕获时终止旧拖动。
- 滚动时角色随自己的文档区域进入/离开视口；角色不能因为旧手动位置而停在屏幕上压住后来滚入的正文。
- 位置采用区域内相对坐标，resize后保持区域内意图；菜单的焦点、关闭与回焦流程复用。
- 旧全视口自由拖动可以保留为显式兼容配置，不新增入口，默认嵌入遵循本轮要求。旧自由拖动测试/报告只证明其当时模式，不证明嵌入已经实现。

### 3.3 复用成熟渲染能力

推荐保留当前同一个PIXI背景/角色舞台与ticker，通过既有`getRegion()`读取只读DOM几何，使模型真正按区域定位。模型自身使用区域mask，点击表面发布相同的可见边界。

已核对本机PIXI **6.5.10**及其公开`DisplayObject.mask`类型/说明：可复用`Container`、矩形`Graphics` mask；mask须处于正确父子树，并在resize/destroy中复用/释放。模型局部bounds用于contain，mask不加入模型自身bounds计算，避免几何反馈。这个方案无需第二个canvas/ticker或新依赖。

DOM区域的`overflow:hidden`不能裁切同一全屏WebGL舞台里另处渲染的模型；“有一个占位div”也不等于已经嵌入。验收以实际渲染、滚动位置和热区是否都服从区域为准。

另建角色canvas会增加渲染/资源生命周期管理，单纯缩小视口漂浮角色仍不能约束拖动和遮挡。本轮推荐复用现有舞台的区域几何与成熟mask能力，改动集中在表现边界。

## 5. 接近角色和控件时的消失行为

### 5.1 排除区域

复用当前控件排除规则：导航、按钮、链接、输入、加载层、角色菜单等。为角色区域/可见交互表面增加明确的DOM排除标记，跟随组件只读标记与几何，不import角色或下载核心。

当前模型交互表面带`role=button`，直接命中已经会恢复原生指针。本轮改进覆盖“接近时的连续消失”和“圆形足迹触碰角色”的阶段，不能只追加一个hover选择器就视为完成。

- 普通控件以指针进入其接近带/实际命中为排除依据。
- 角色以镜片**未缩放的基准圆形足迹**与可见角色区域的距离判定：圆形将接触角色时开始避让，不能等遮住人物后才消失。
- 排除判定不跟着正在缩小的圆径变化；退出需要额外余量，避免“缩小→离区→放大→再次进入”的循环。
- 角色区域收起/不可用时不留下虚假的全屏排除矩形；角色移动/resize/滚动/场景切换后更新同一边界。

### 5.2 状态与过渡

| 状态 | 圆形 | 指针与标题 |
| --- | --- | --- |
| 展示区跟随 | 正常尺寸，保留原生反相/位置缓动 | 当前展示标题倾斜 |
| 接近/进入排除区 | 从当前状态缩小并淡出至不可见 | 立即恢复控件原生指针；角色保持grab/grabbing；标题平滑回正 |
| 离开并回到允许区 | 先定位到新指针位置，再从较小尺寸恢复 | 不从屏幕角落飞入、不沿用旧隐藏位置；指针交接不产生两者都不可见的空档 |
| 拖动、blur/hidden或系统禁用 | 清除活动状态，圆形不可见 | 原生指针可用，角色拖动/菜单按各自生命周期清理 |

定位层与缩放/透明度层分开，复用CSS`transform`/`opacity` transition；不动画宽高，不增加RAF/逐帧碰撞或GPU像素读取。快速往返时过渡从当前可见状态继续，最终允许/禁止状态直接设置，不依赖transitionend决定交互是否可用。

几何在既有布局刷新时缓存。角色交互面位于uiRef外的舞台内，排除读取必须覆盖该DOM表面；只观察相关边界的变化，不能对全document的style变化监听而把镜片自己写style的动作反馈成无限刷新。reduced-motion/forced-colors/触屏/窄屏禁用规则继续适用。
