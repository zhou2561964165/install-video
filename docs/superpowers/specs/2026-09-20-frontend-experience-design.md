## 1. 目标与定位

把「视频下载」这个工具，做成一场**可交互的二次元短篇体验**：用户在完成「解析 → 选清晰度 → 下载」的同时，获得「进入一个微型世界」的感受。

三条贯穿始终的原则：

1. **叙事驱动**：整个体验分成若干章节（= 四个下载阶段），无传统导航，用户通过粘贴、点击、滑动推进，界面随交互逐步揭开。
2. **UI 嵌入插画**：界面元素不是独立浮层，而是融入背景插画叙事（对话框 = 漫画气泡、通知 = 弹幕）。
3. **微交互即反馈**：每个操作都有视觉 + 听觉的即时回应。

> **v1 优先级**：先跑通「解析 → 选清晰度 → 下载」功能闭环（后端 + 前端基本流程）；视觉氛围与角色互动分层实现——功能先行，动效不阻塞下载。角色互动、换角色留待后续（见 §9）。

## 2. 视觉语言

### 2.1 色彩体系：多层动态渐变 + 高饱和霓虹

**底色**（深空系，营造纵深）：深空黑、午夜蓝、暗紫。

**叠加色**（高饱和霓虹，制造光感）：品红、电光蓝、青柠、琥珀、珊瑚橙、紫罗兰、薄荷绿、镭射粉、虹彩色。

**背景形态**（避免单一粉蓝紫的单调感）：
- 极光带、全息光晕、液态金属、流体渐变、渐变网格
- 色相缓慢偏移的流动背景（持续、低幅、呼吸感）

**附加质感**：光斑（bokeh）、色散（chromatic dispersion）、渐变噪点、亮度呼吸。

### 2.2 背景持续动效（常驻底层）

樱花飘落、气泡上升、星星闪烁、光尘漂浮、粒子旋流。

> 动效分「安静 / 活跃」两档强度，由场景状态切换（见 §6）：入口/选择阶段偏安静，解析/下载阶段加速。

### 2.3 UI 元素视觉语言

| 元素 | 视觉形式 |
| --- | --- |
| 对话框 | 漫画气泡（对话/提示用） |
| 系统通知 | 弹幕式，从屏幕边缘滑入 |
| 边框 | 镭射渐变边框、彩虹描边 |
| 加载进度 | 发光能量条 |
| 下载进度 | 粒子汇聚（向进度环/能量条汇聚的粒子隐喻） |
| 交互动效 | 切割、RGB 分离、速度线 |

## 3. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 渲染引擎 | **PIXI.js（单一 WebGL 管线）** | 背景场景 + Live2D 角色同处一个 PIXI Stage |
| 背景场景 | PIXI（渐变/极光/粒子/樱花/气泡/星星/光尘/旋流/进度粒子） | shader + filter + particle emitter 实现 |
| 引导角色 | pixi-live2d-display | 渲染 Cubism 3 Live2D 模型，与背景同管线 |
| Live2D 运行时 | Cubism Core（`live2dcubismcore.min.js`） | 生产环境**自托管**，不依赖外链 |
| UI 层 | React + DOM/CSS | 卡片、气泡、按钮、弹幕、镭射边框 |
| 音频 | Web Audio API / HTML5 Audio | SFX + BGM（详见 §7） |
| 构建 | Vite（同 design.md） | — |

**单一渲染管线**（两「层」同一 Stage，UI 层为 DOM 叠加）：
1. **场景层（PIXI Stage）**：背景渐变/粒子/动效 与 Live2D 角色同处一个场景图——角色可与背景粒子互动、后续可加角色互动与换角色。
2. **UI 层**：DOM/CSS 元素（React）叠加在最上，负责文本类/可交互控件、气泡、弹幕、卡片。

> **选型理由**：pixi-live2d-display 基于 PIXI.js，Live2D 生态没有成熟的 Three.js 渲染器；要在「同一管线」里统一背景与角色，PIXI.js 是唯一干净的选择——背景所需的渐变/极光/RGB 分离/粒子全部可由 PIXI 的 shader + filter + particle emitter 承担。统一到一个 Scene Graph 后，角色互动、换角色、角色与背景联动的扩展成本最低。

## 4. 状态机与数据流

前端维护一个**场景状态机**（Scene State Machine），后端 API 状态映射到它：

```
backend API 状态            →  场景状态（scene）        →  各层动效
─────────────────────────────────────────────────────────────
无任务                     →  entry(入口)              → 背景安静、角色待机
POST /api/parse 中         →  parsing(解析中)          → 背景加速、角色思考、加载动画
parse 成功                 →  selecting(信息选择)       → 卡片入场、角色待机/好奇
parse 失败                 →  error(错误场景)          → 按 error_type 渲染
POST /api/download 中      →  downloading(下载中)       → 进度粒子、角色奔跑、背景活跃
下载完成                   →  done(完成)               → 完成动画、角色庆祝
```

> 错误场景沿用 `design.md §8` 的统一错误分类（invalid_url / unsupported_site / age_restricted / geo_blocked / drm / login_required / ffmpeg_missing / network / quota），每种对应一套「二次元错误场景」视觉 + 气泡提示文案。

## 5. 引导角色（Live2D）

### 5.1 模型与授权

- 模型：初音未来 Live2D，**Cubism 3.0**（`miku.model3.json` + `miku.moc3` + 6 张 4096 纹理 + `miku.physics3.json` + `miku.cdi3.json`）。
- 资源位置：开发期从 `D:\QAQ\miku\miku\miku\` 复制进项目（建议 `frontend/public/live2d/miku/`）。
- **授权**：已获作者许可使用。出处注明：人物绘制 玄宝酱 / 建模 怂怂koe（保留在 README / 关于页）。
- 水印：`水印.exp3.json` 默认开启；**经授权关闭**（初始化时不置为默认表情，水印不显示）。

### 5.2 状态 → 动作/表情映射

模型提供 motion 组（`Scene1.motion3.json`）与多个 expression（`圈圈 / 脸红 / 葱 / 唱歌 / 比心 / 前倾 / QQ人` 等）。

| 场景状态 | 角色反馈 | 实现方式 |
| --- | --- | --- |
| entry | 待机（呼吸 + 眨眼，EyeBlink 自动） | 默认 + 空闲 motion |
| parsing | 思考 | 对应 expression（如 `圈圈`）+ 轻缓左右摆动 |
| selecting | 好奇/期待 | 对应 expression（如 `脸红`） |
| downloading | 奔跑/努力 | motion（若模型有移动类动作）+ 角色横向位移 + 速度线补充 |
| done | 庆祝 | motion（如 `比心`/`唱歌`）+ 完成动画 |
| error | 沮丧/疑惑 | 对应 expression（如 `哭哭`）+ 气泡提示 |

**约束**：模型未必有字面意义的「奔跑」动作——此时用「循环 motion + 角色水平位移动画 + 速度线」组合表达，不强求模型没有的动作。

### 5.3 已知调整点

模型 `model3.json` 的 `FileReferences` 目前只含 Moc/Textures/Physics/DisplayInfo，**未声明 Motions/Expressions**。web 渲染前需二选一：
- 在 `model3.json` 补 `Motions`（指向 `Scene1.motion3.json`）与 `Expressions`（逐条指向 `.exp3.json`）引用；或
- 在代码里用 `motionManager` / `expressionManager` 程序化加载。

## 6. 四阶段分镜

### 阶段一 · 入口（entry）

- **视觉**：全屏二次元动画背景持续运行（§2.2 动效，安静档）；中央「粘贴链接」区域设计为**发光气泡 / 魔法阵**。
- **交互**：粘贴链接或拖入 → 触发一次视觉反馈动画（气泡破裂 / 光芒扩散）→ 进入解析。
- **角色**：待机。
- **音频**：BGM 起；粘贴成功播 SFX。

### 阶段二 · 解析（parsing）

- **视觉**：背景动效**加速**；屏幕边缘出现流动光线 / 粒子轨迹；中央解析进度用二次元加载动画（旋转星形 / 聚集粒子）替代传统转圈。
- **交互**：无（等待后端 `POST /api/parse`）。
- **角色**：思考表情 + 轻摆。
- **音频**：BGM 节奏变化 / 解析音效。

### 阶段三 · 信息选择（selecting）

- **视觉**：解析成功后，**卡片式布局**展示封面图、标题、时长、可选清晰度（360p / 720p / 1080p / 4K）与封装格式。卡片带二次元边框动画，**悬停浮起 + 发光**；清晰度选项以**标签/徽章**呈现，选中态明显高亮。
- **交互**：点选清晰度 → 进入下载；提供「强制走服务器」开关（对应 design.md §5 兜底）。
- **角色**：好奇/期待。
- **音频**：选中 SFX。

### 阶段四 · 下载（downloading → done）

**三层反馈**：
1. **进度层**：发光能量条 / 环形粒子进度（直链模式则直接触发浏览器下载，无此层）。
2. **状态层**：引导角色动作变化（奔跑 → 完成庆祝）。
3. **氛围层**：背景动效由安静切换到活跃（如樱花加速飘落、粒子旋流加强）。

- **完成**：播放简短完成动画，提供「打开文件 / 继续下载」选项。
- **直链模式**：`{mode:"direct"}` 时前端直接浏览器下载，角色/氛围做一次短暂「发送」动效。
- **服务端模式**：轮询 `GET /api/job/{id}`，进度驱动上述三层。

## 7. 音频设计

- **SFX**：粘贴成功、解析开始、清晰度选中、下载完成、错误提示等短音效。
- **BGM**：环境背景乐，随场景切换情绪（安静 → 加速 → 庆祝）。
- **自动播放策略**：默认尝试自动播放（用户选择）；移动端浏览器会拦截未授权音频——**首次用户手势（粘贴/点击）时解锁音频上下文**作为回退。
- **资产**：BGM/SFX 音源需另行准备（spec 不包含具体音频文件）；可先用占位/可商用音源。

## 8. 性能与降级策略（保住 R6 手机可下载）

全屏 WebGL + Live2D 在低端机有性能风险，做分级降级：

1. **WebGL 检测**：无 WebGL 时回退到纯 CSS 渐变背景 + 静态角色图。
2. **移动端 / 低端机**：自动降低粒子数量、关掉色散/噪点等后处理、Live2D 降到较低帧率。
3. **手动「轻量模式」开关**：用户可主动关闭背景动效，仅保留角色 + UI，保证下载功能可用。
4. **下载功能与视觉解耦**：任何动效卡顿都不得阻塞下载请求本身——下载逻辑始终可独立跑通。

## 9. 与设计文档的关系 / 扩展点

- **接口契约**：完全复用 `design.md §4`（`POST /api/parse`、`POST /api/download`、`GET /api/job/{id}`、`GET /api/file/{id}`）与 `§5`（直链/服务端切换）。本文档只决定「这些状态如何被视觉化」。
- **核心约束不变**：`ytdlp_service.py` 仍是唯一接触 yt-dlp 的层；前端不感知下载核心。
- **预留**：Live2D 角色互动（点击/拖拽/角色与背景粒子联动）、换 Live2D 角色（模型可插拔）、主题切换（多套氛围）、更多角色动作/服装、SSE 替代轮询（后续可加）。统一 PIXI 管线使这些扩展成本最低。
