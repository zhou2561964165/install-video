代码整改已落地，真实质量尚未收尾。三个角色并行实施后，平台使用额度使子 Agent 无法继续；主 Agent 接手检查、回归及验收工具，没有宣称独立 Agent 审查通过。

## 改动

- summary_normalization：完整段落或条目先规范化，保留原文、数字、条件和引用提示，拒绝未知结构及超限，不截字删点。
- summary_references：程序从已验证事实提供精确或词法关联，记录依据、冲突、无效提示和歧义；引用 ID 和分数不等于语义证明。
- summary_retry：格式和语义分别计数，默认各 1 次、合计最多 2 次；可以关闭。来源、网络、供应商、容量和配置错误不重试。
- llm_service：只负责编排和 HTTP；最终仍执行来源、核心覆盖、逐项核查与严格长度限制。公开 API 和默认 legacy 保持。

## 已定位的格式故障

长文两份原响应实际有 fact_1–fact_10，且字段内容符合来源协议；多出的 `type: "json_object"` 是供应商重复的输出格式标记。后续离线修复仅识别这个明确的无内容格式标记，不删除未知字段，不改变事实文本、证据、归因或数量。两份原件均在本地解析出 10 条来源有效事实。另建 [marker 复验](../2026-10-08-grounded-summary-marker/report.md)，原阶段失败与冻结证据保持原样。
