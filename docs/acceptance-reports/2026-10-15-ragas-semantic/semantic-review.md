## 真实 P4 的独立判断

原 P4 开头是“历史上，固定程序计算机（如计算器）只懂加、减、乘、除，不能绘图、发邮件或上网”。“如计算器”提供例子，没有将谓词限制到该例子；语法主语仍是固定程序计算机类别。来源在 596–600 行介绍类别，607–608 行提醒现在的计算器更复杂，609–611 行转到具体 `this calculator`；612–620 行的 `It` / `with it` 承接该例子。类别下有这个例子不蕴含全类别只有它的能力。

| 原 P4 断言 | 自动判断及 reason 的问题/依据 | 独立结论 |
| --- | --- | --- |
| S1 固定程序计算机（如计算器）只懂四则 | reason 说类别的一个例子是计算器，计算器只懂四则。它只证明实例谓词，没有证明类别谓词；609–614 行的主语跳转被忽略。 | **不支持，verdict=1 为误放。** |
| S2 固定程序计算机不能绘图、发邮件或上网 | reason 引用“你不能”的三个限制，未把 `with it` 绑定到前述计算器，因而将 615–619 行的实例限制推广到类别。 | **不支持，verdict=1 为误放。** |
| S3 固定程序计算机要做另一件事就得另造机器 | 621–626 行直接以“做另一件事”的条件说明另造固定程序机；这是固定任务与可换指令的对照，不是“所有固定程序机仅做四则”的论据。reason 的“完全独立的测试”来自字幕措辞；原断言只保留换任务另造机器。 | 支持；不因 S1/S2 错误连带否定此句。 |
| S4 能存储指令序列 | reason 与 628–632 行一致。 | 支持。 |
| S5 能执行所存指令序列 | reason 与 633–634 行一致。 | 支持。 |
| S6 可改变指令序列并执行不同指令 | reason 与 635–638 行一致；原句是可更换程序，不是机器无外部操作自发改写自己。 | 支持。 |
| S7 同一机器可做不同任务 | reason 与 639–640 行一致。 | 支持。 |
| S8 就是今天的计算机 | reason 与 641–642 行的讲座概括一致；应按授课语境理解，不另认证所有现实设备的分类。 | 支持。 |

局部纠正点改成“讲座举出的旧计算器是固定程序计算机的一个例子，它……”；这仅纠正 P4 主体，不是重新生成完整产品总结。

## 误放、误拒与接入边界

本次按八例全支持/非全支持计：预期支持四例均接受，预期不支持四例中拒绝三例、误放一例（原 P4），误拒零例。独立判断与预先标签一致。以实际抽取的 27 条断言观察，明确的错误支持有两条，均在原 P4；其余 25 条判定本次可接受。断言由 judge 自行切分，正负例条数也不同，这个计数不是独立抽样准确率，不能用于可靠性保证。

**不能接成唯一生产放行门，也不能因六条合成对照通过而升级默认策略。** 已知真实缺陷正好是需拦截的失败模式；原点与局部纠正点得分完全相同，阈值调到 1.0 也不能区分。成熟框架提供可复用分解/NLI流程，不能消除 judge 本身的语义误判。

可保留独立开发诊断用途：展示原响应、抽取断言、逐条 reason/verdict 和人工复核入口，经窄接口调用，不让评测分数直接改写下载/总结核心状态。本报告没有实现此接入或自动修复。后续若评估生产接入，至少需要来源体裁更多样、未见真实内容、跨语言范围/归因/否定等独立标注，以及与已知 P4 类缺陷的检出证据；当前没有这些结果，不在本报告自动触发新调用。

Faithfulness 只问已生成断言是否可由来源支持。六例合成样本的 `core_questions` 未测量，完整 MIT 的 core 覆盖也未在本轮测量；不能用本轮分数推断摘要有无漏掉重要主题、关键条件或下一讲衔接。组织、概览职责、冗余、完整产品总结、新流程短中回归与未见讲座泛化均不在这八例的验证范围。两个 MIT 样本共享同一来源和几乎相同响应，只构成 P4 的局部对照，不能当作两份独立长文产品验收。
