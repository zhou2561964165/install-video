## 0. 工程约定（每次遵守）

> 与根目录 `CLAUDE.md` 一致（最高优先级）。

1. **UI 必须用 skill**：配色/字体/动效/无障碍/组件先调用 `ui-ux-pro-max` + `design-system`。
2. **skill 优先于计划**：冲突时以 skill 为准（如「每屏最多动 1–2 个关键元素」> 常驻动画清单）。
3. **不写死、保留扩展**：颜色/字体/时长走 `:root` token；新增能力数据驱动、可配置，避免大规模重构。
4. **解耦**：核心模块对外只暴露窄接口（后端 `ytdlp_service.py` 唯一接触 yt-dlp；前端视觉层只读 `scene`、不改下载状态、不 import 下载核心）；层与模块通过稳定接口通信，扩展不触碰既有核心。

## 1. 项目目标

做一个支持登录用户视频下载与AI内容总结的网站：保留解析、清晰度选择和保存到本地的核心能力；v3以理解内容、生成摘要和关键要点为主，字幕是内容来源，允许去掉重复内容并分段归纳。手机端可用。

## 2. 背景与痛点

- 很多平台的视频无法直接下载（不提供下载功能）
- 部分平台下载不便：不支持批量、有各种限制、清晰度有限
- 希望随时随地、跨平台、在手机端也能下载

## 3. 核心需求（v1 必须完整可用）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 粘贴链接 | 输入任意支持的视频 URL |
| R2 | 解析视频 | 展示标题、封面、时长、可选清晰度列表 |
| R3 | 选择清晰度 | 用户可挑选分辨率（如 1080p / 720p …）与封装格式 |
| R4 | 下载 | 把视频保存到用户本地/手机 |
| R5 | 多平台 | 依托 yt-dlp，覆盖数千站点 |
| R6 | 手机可下载 | 下载结果在移动端浏览器可用 |

> 功能逻辑必须完整可用；视觉呈现见 §5。

## 4. 下载方式（已确认）

**直链下载 + 服务端下载，自动切换：**
- 优先返回直链，由浏览器直接下载（最快、最省服务器资源）
- 直链不可用 / 过期 / 需 cookie 时，自动落到服务端下载再转发给用户
- UI 提供「强制走服务器」手动兜底开关

## 5. 视觉与交互要求（重要，不可平庸）

- 前端页面**足够独特，不千篇一律**
- 参考 **2019.makemepulse.com** 的交互形式与视觉氛围
- 将核心美学从「莫比乌斯风格的漫画素描」**彻底转化为日系二次元风格**
- 下载功能逻辑完整可用，但界面应像一场**可交互的二次元短篇体验**——用户在「使用工具」的同时获得「进入一个微型世界」的感受

> **参考站关键手法**（已对照 2019.makemepulse.com 提取，第二阶段落实，见 §9）：蒙版揭幕、圆形虹膜转场、几何画框、章节字幕叙事、自定义动画光标、分段分层按钮、缠绕式进度。

## 8. 扩展状态与后续方向

当需要实现时，先在本文档登记需求，再更新 `design.md`：
1. ✅ AI内容总结（含去重、长文分段归纳与合并）
2. ✅ 字幕内容获取 + 翻译（辅助能力）
3. 付费能力（会员 / 支付渠道；额度已随 v2 落地）
4. ✅ **账号体系 + 每用户额度（v2，2026-10-03 完成强制登录收口）**：注册/登录（JWT）+ 每用户每日下载额度；`/api/parse`、`/api/download` 均要求 Bearer token，不再允许匿名解析或下载。
5. 批量下载
6. 任务队列横向扩展（Celery / Redis）

### 8.1 v3 视频智能（2026-10-03 MVP 已实现）

1. 登录用户可在解析结果页读取视频的手工字幕；没有手工字幕时允许回退自动字幕。
2. 支持把选定字幕翻译到目标语言，首版默认目标语言为简体中文。
3. 支持基于字幕生成短摘要和关键要点；没有字幕时明确提示，不静默改用音频转写。
4. LLM 供应商、base URL、模型、API key、超时和最大输入长度必须配置化；未配置时字幕读取仍可用。
5. v3 首版由用户显式触发，不自动消耗下载额度，不阻塞既有解析和下载流程。
6. v3 API 必须登录；字幕/LLM 错误在功能面板就地展示，不把下载状态机切到全局错误场景。
7. AI 内容总结为主，字幕只是内容来源。总结输入可以去重；长内容按可配置大小分段归纳，再合并为摘要和要点，末尾内容也应参与总结。翻译输入超限仍明确提示。
8. 模型输出因长度限制未完成时提示重试；对单次总结设置可配置的分段数量与输出预算。
9. 若视频解析阶段没有返回字幕语言列表，视频智能面板仍保留显式字幕读取、翻译与总结入口，并提供自动选源语言；不自动发起请求，实际无字幕或平台错误在面板中说明，不关闭下载流程。

**MVP 验收状态**：已实现 `POST /api/subtitle`、`POST /api/subtitle/translate`、`POST /api/summary`，支持 VTT/SRT/JSON3/TTML；前端解析结果页已接入独立视频智能面板。

## 9. 第二阶段：电影感视觉升级（前端）

> 以下是2026-09-22历史设计，不作为当前待办。当前主题为深色液态玻璃与樱花粉辉光，最新状态和后续范围以 `handoff.md` 为准。

> 登记日期：2026-09-22。v1 已跑通「解析 → 选清晰度 → 下载」核心闭环并完成基础二次元视觉；本阶段对照参考站 2019.makemepulse.com 补齐「电影感」手法，映射到二次元风格。

| 编号 | 手法 | 二次元等价 | 说明 |
| --- | --- | --- | --- |
| V1 | 蒙版揭幕 + 虹膜转场 | 魔法阵传送门收放 + 标题逐字揭开 | 场景切换如「翻页」 |
| V2 | 几何画框 | 四角画面边框 | 界面如「漫画分格」 |
| V3 | 章节台词 | 底部叙事字幕 | 每阶段一句台词，串起叙事 |
| V4 | 自定义光标 | 光标随场景变样（解析=圈圈 / 完成=比心） | 强化「进入世界」感 |
| V5 | 分段分层按钮 | 主按钮三段逐段点亮 | 关键交互的「电影感」 |
| V6 | 缠绕式进度 | 魔法符文 / 星光轨迹进度 | 替代普通横条 |

**阶段原则（约束所有视觉升级）**

1. **核心流程优先**：每一处视觉升级都必须先保证「解析 → 选清晰度 → 下载」端到端可运行、可验证；视觉是叠加层，绝不阻塞下载。
2. **预留扩展**：台词 / 转场 / 光标 / 进度全部配置外置、数据驱动；后续扩展（新场景、新错误、视频总结/字幕翻译的台词注入、主题切换）改配置不改代码。
3. **避免过度设计**：不做 v1 用不到的抽象；但核心逻辑不写死，避免后续大重构。
