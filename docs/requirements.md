## 1. 项目目标

做一个支持登录用户视频下载与AI内容总结的网站：未登录用户可访问首页并输入视频URL，解析、下载及内容API仍要求认证；登录/注册由顶部按钮显式进入。保留解析、清晰度选择和保存到本地的核心能力；v3以理解内容、生成摘要和关键要点为主，字幕是内容来源，允许去掉重复内容并分段归纳。手机端可用为目标，实际设备验证范围按对应报告记录。F-006已实现并验证，等待用户查验，范围见[实施报告](implementation-reports/2026-10-17-f006.md)。

2026-10-16架构审视已按源码区分：前端App组合认证/下载/内容独立状态，后端为同步业务请求与专用下载池并存的模块化单体；SQLite保存业务记录，不能据此承诺执行恢复、取消或全局并发限制。独立Pro全文runner与Ragas不属于公开总结路由。实际架构见[design](design.md#1-架构总览)，结构风险与后续事项统一见[总表F-005](follow-up-plan.md#9-f-005技术架构审视2026-10-16)。

## 2. 背景与痛点

- 很多平台的视频无法直接下载（不提供下载功能）
- 部分平台下载不便：不支持批量、有各种限制、清晰度有限
- 希望随时随地、跨平台、在手机端也能下载

## 3. 核心需求（v1 必须完整可用）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 粘贴链接 | 输入任意支持的视频 URL |
| R2 | 解析视频 | 展示标题、封面、时长、可选清晰度列表 |
| R3 | 选择清晰度 | 用户可挑选分辨率（如 1080p / 720p …）与封装格式 |

> 功能逻辑必须完整可用；视觉呈现见 §5。

## 4. 下载方式（已确认）

**网页默认按视频标题命名，保留可选直链：**
- 网页默认勾选“按视频标题命名”，使用已有服务端下载及原标题文件名响应
- 取消选项后优先返回来源直链；来源站决定浏览器保存的文件名
- 直链探测无结果或抛错时，仍自动落到服务端下载
- API未传 `force_server` 时保留旧默认false；两种方式仍各按提交扣1次额度

当前前端通过浏览器跳转打开直链，不附加返回的HTTP请求头；浏览器侧过期、保存或请求头限制不会自动重提服务端任务。当前 `POST /api/download` 的开关字段为 `force_server`，详见 `design.md` §4–5。

### 8.1 v3 视频智能（2026-10-03 MVP 已实现）

> 下列长内容分段/合并描述保留内部能力及早期目标。2026-10-12公开入口仅开放正文上限内的短篇和中篇总结，长文提示暂不支持，具体以§8.6为准。

1. 登录用户可在解析结果页读取视频的手工字幕；没有手工字幕时允许回退自动字幕。
2. 支持把选定字幕翻译到目标语言，首版默认目标语言为简体中文。
3. 支持基于字幕生成概览摘要和关键要点，按字幕规模与必要条件有限拓展；没有字幕时明确提示，不静默改用音频转写。
4. LLM 供应商、base URL、模型、API key、超时和最大输入长度必须配置化；未配置时字幕读取仍可用。
5. v3 首版由用户显式触发，不自动消耗下载额度，不阻塞既有解析和下载流程。
6. v3 API 必须登录；字幕/LLM 错误在功能面板就地展示，不把下载状态机切到全局错误场景。
7. AI 内容总结为主，字幕只是内容来源。总结输入可以去重；长内容按可配置大小分段归纳，再合并为摘要和要点，末尾内容也应参与总结。翻译输入超限仍明确提示。
8. 模型输出因长度限制未完成时明确提示错误；对单次总结设置可配置的分段数量与输出预算。默认路径不自动重发计费请求，facts实验的分类修复范围见 §8.6。
9. 若视频解析阶段没有返回字幕语言列表，视频智能面板仍保留显式字幕读取、翻译与总结入口，并提供自动选源语言；不自动发起请求，实际无字幕或平台错误在面板中说明，不关闭下载流程。
10. 当前视频功能采用用户指定参考项目的白蓝双栏与操作结构：下载状态和内容同屏、解析后预选首个格式；解析中及所有视频状态提供返回输入、链接保留、焦点及迟到响应保护。已有摘要/字幕/翻译页签支持键盘，显式处理、复制及完整TXT导出；字幕时间戳/SRT/VTT、思维导图/问答仍未接入。参考自动模型调用不适用于当前显式生成要求。
11. **字幕轨道反馈（2026-10-13）**：用户报告B站`BV1B84y1q7Hr`读取字幕时显示“平台字幕轨道结构无效”。本轮核对本地实现，空轨道列表表示无字幕；B站`subtitle`或嵌套`subtitles`返回`null`/类型不符时会报结构错误。没有重取示例视频API响应，实际payload及该视频字幕可用性仍待确认。

**MVP 验收状态**：已实现 `POST /api/subtitle`、`POST /api/subtitle/translate`、`POST /api/summary`，支持 VTT/SRT/JSON3/TTML；前端解析结果页已接入独立视频智能面板。

**阶段原则（约束所有视觉升级）**

1. **核心流程优先**：每一处视觉升级都必须先保证「解析 → 选清晰度 → 下载」端到端可运行、可验证；视觉是叠加层，绝不阻塞下载。
2. **预留扩展**：台词 / 转场 / 光标 / 进度全部配置外置、数据驱动；后续扩展（新场景、新错误、视频总结/字幕翻译的台词注入、主题切换）改配置不改代码。
3. **避免过度设计**：不做 v1 用不到的抽象；但核心逻辑不写死，避免后续大重构。
