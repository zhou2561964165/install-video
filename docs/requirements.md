## 1. 项目目标

做一个支持登录用户视频下载与AI内容总结的网站：保留解析、清晰度选择和保存到本地的核心能力；v3以理解内容、生成摘要和关键要点为主，字幕是内容来源，允许去掉重复内容并分段归纳。手机端可用。

## 2. 背景与痛点

- 很多平台的视频无法直接下载（不提供下载功能）
- 部分平台下载不便：不支持批量、有各种限制、清晰度有限
- 希望随时随地、跨平台、在手机端也能下载

## 3. 核心需求（v1 必须完整可用）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| R1 | 粘贴链接 | 输入任意支持的视频 URL |
| R2 | 解析视频 | 展示标题、封面、时长、可选清晰度列表 |
| R3 | 选择清晰度 | 用户可挑选分辨率（如 1080p / 720p …）与封装格式 |
| R4 | 下载 | 把视频保存到用户本地/手机 |
| R5 | 多平台 | 依托 yt-dlp，覆盖数千站点 |
| R6 | 手机可下载 | 下载结果在移动端浏览器可用 |

> 功能逻辑必须完整可用；视觉呈现见 §5。

## 4. 下载方式（已确认）

**直链下载 + 服务端下载，自动切换：**
- 优先返回直链，由浏览器直接下载（最快、最省服务器资源）
- 直链不可用 / 过期 / 需 cookie 时，自动落到服务端下载再转发给用户
- UI 提供「强制走服务器」手动兜底开关

## 5. 视觉与交互要求（重要，不可平庸）

- 前端页面**足够独特，不千篇一律**
- 参考 **2019.makemepulse.com** 的交互形式与视觉氛围
- 将核心美学从「莫比乌斯风格的漫画素描」**彻底转化为日系二次元风格**
- 下载功能逻辑完整可用，但界面应像一场**可交互的二次元短篇体验**——用户在「使用工具」的同时获得「进入一个微型世界」的感受

> **参考站关键手法**（已对照 2019.makemepulse.com 提取，第二阶段落实，见 §9）：蒙版揭幕、圆形虹膜转场、几何画框、章节字幕叙事、自定义动画光标、分段分层按钮、缠绕式进度。

## 8. 扩展状态与后续方向

当需要实现时，先在本文档登记需求，再更新 `design.md`：

2. ✅ 字幕内容获取 + 翻译（辅助能力）

5. 批量下载
6. 任务队列横向扩展（Celery / Redis）

### 8.1 v3 视频智能（2026-10-03 MVP 已实现）

1. 登录用户可在解析结果页读取视频的手工字幕；没有手工字幕时允许回退自动字幕。
2. 支持把选定字幕翻译到目标语言，首版默认目标语言为简体中文。
3. 支持基于字幕生成短摘要和关键要点；没有字幕时明确提示，不静默改用音频转写。
4. LLM 供应商、base URL、模型、API key、超时和最大输入长度必须配置化；未配置时字幕读取仍可用。
5. v3 首版由用户显式触发，不自动消耗下载额度，不阻塞既有解析和下载流程。
6. v3 API 必须登录；字幕/LLM 错误在功能面板就地展示，不把下载状态机切到全局错误场景。
7. AI 内容总结为主，字幕只是内容来源。总结输入可以去重；长内容按可配置大小分段归纳，再合并为摘要和要点，末尾内容也应参与总结。翻译输入超限仍明确提示。
8. 模型输出因长度限制未完成时提示重试；对单次总结设置可配置的分段数量与输出预算。
9. 若视频解析阶段没有返回字幕语言列表，视频智能面板仍保留显式字幕读取、翻译与总结入口，并提供自动选源语言；不自动发起请求，实际无字幕或平台错误在面板中说明，不关闭下载流程。

**MVP 验收状态**：已实现 `POST /api/subtitle`、`POST /api/subtitle/translate`、`POST /api/summary`，支持 VTT/SRT/JSON3/TTML；前端解析结果页已接入独立视频智能面板。

### 8.2 增量覆盖与质量验收（2026-10-04）

- 扩大真实平台字幕样本，区分访问限制、网络失败和实际无字幕。公开字幕元数据适配有收益时可增加专用提取器；任一专用路径不可用时继续保留yt-dlp回退。
- 补齐注册/登录/刷新/退出及解析→选择→下载、字幕读取/翻译/总结的浏览器流程。桌面与375px均检查；本机媒体、字幕与LLM协议夹具的成功不计为公网平台成功。
- 短、中、长内容总结使用独立可核对的事实、数字和尾部结论验收。根据测得缺陷改善摘要与要点；短内容不应为了要点数量扩写来源未提供的内容或重复相同观点。
- 专用适配、验收工具和质量改进通过既有服务边界接入；本阶段不新增字幕时间轴/导出、自动音频转写、问答、思维导图或支付。

本轮已完成：Bilibili公开字幕及原生/通用inline回退、双视口本机真实API流程与独立Archive公网页面总结、三组真实模型before/after质量核查。总结提示允许1–7条完整、不同的重要事实；残余长内容冗余和公网未覆盖范围见[本轮报告索引](README.md)。

### 8.3 自然字幕与公网移动/GPU追加（2026-10-04）

- 用户已授权继续自然中英文字幕的独立事实核查，并针对测得问题改进长内容要点组织；先冻结有明确许可的自然源与事实，使用相同语料及默认分段配置进行真实模型前后对照。新预算最多24次实际POST，包含每段与合并，不覆盖旧台账。
- 相同主旨的原因、条件与例子可以合并成完整要点，不能因关键词相似删除不同事实；尾部结论与准确数字继续保留，摘要/关键要点接口不变。
- 公网375px流程须实际保存文件并核对音视频/时长；默认WebGL验收记录设备、纹理上限、实际上传和角色画面。桌面移动视口不作为真手机兼容证明，布局和全交互另行验收。
- 语料使用与软件许可分开，MIT OCW样本仅用于遵守CC BY-NC-SA4.0的非商业评测；不作为无约束商用产品数据。
- 已测到的输出格式和推理耗尽预算问题通过可配置的摘要请求选项处理：DeepSeek摘要auto使用JSON模式并关闭推理，其他通用供应商auto及翻译不额外携带选项。保持严格结构和完成状态校验，不自动重发计费请求。

已交付输出控制及1–7点严格校验 `05753e7`，184/66及构建通过；真实字幕24次POST、公网375px保存与当前Windows GPU另行留证。语义主事实覆盖不等于每条claim准确：长末条426字、通常→总是的频率强化与例子范围泛化仍需改进，长组织目标未达标。范围、文件分工与结果见[追加计划](superpowers/plans/2026-10-04-natural-quality-mobile-gpu.md)和[最新交接](handoff.md)。

### 8.4 严格schema与响应式布局（用户授权继续）

- 核实并接入供应商可约束字段和1–7条数量的schema摘要协议，必要的要点长度上限配置化；本地同时校验，错误不通过截断、补写或自动发第二次计费请求掩盖。通用供应商、翻译与显式兼容模式保持可选。
- 复用固定自然字幕与事实检查长文重点、频率/模态和具体例子范围，schema符合不当作事实准确。新模型台账最多20次POST，能力探针和分段/合并全计入；旧24次原件不改。
- 手机角色与主控件分开布局，桌面角色按可用区域避免裁切；颜色、间距、交互与布局先经UI技能决策并保持配置/token。验证真实GPU画面、控件和角色交互；真手机可访问时才实测，模拟视口/低GPU不混称真实设备。
- 不修改原角色模型资产、下载状态边界或用户配置，不新增付费、ASR、批量下载、SSE。

实验协议已接入但供应商仍违约，默认未切换。本地严格拒绝、原文边界贯穿merge与响应式角色/焦点/手势修复各自验收；精简和事实完整性仍有残余，不把结构有效当作质量全通过。实施、所有权与结果见[本轮计划](superpowers/plans/2026-10-04-schema-quality-responsive-layout.md)，最终计数和证据见[交接](handoff.md)。

### 8.5 可追溯事实/主题与逐声明核查（2026-10-05继续）

- 在既有摘要服务内增加来源绑定的事实中间层：引用清理后输入的真实片段/位置和哈希，保留限定、归因和重要程度。不能用模型自行给出的span或ID冒充原文核查。
- 组织输出声明并引用已验证事实，计划中的核查阶段检查/修订逐条声明；新增事实也要回查来源，任何来源/引用/结构/负面核查错误明确停止，不自动重试或付费回退。
- 摘要与1–7关键点的公开API保持，trace只给内部诊断/评测，正常请求不持久保存用户字幕；翻译与yt-dlp路径不变。
- 策略、源容量和实验格式组合在发送前选择，保留legacy兼容与长文能力。新24POST台账独立，全部计划阶段/失败计入；旧19/24台账不改。
- 来源字面匹配、模型核查阳性和语义准确分别验收；单次三样本不宣称普遍质量。长文重点/尾部/归因按旧固定事实保守核对，不靠截断降低字数。

## 9. 第二阶段：电影感视觉升级（前端）

> 以下是2026-09-22历史设计，不作为当前待办。当前主题为深色液态玻璃与樱花粉辉光，最新状态和后续范围以 `handoff.md` 为准。

> 登记日期：2026-09-22。v1 已跑通「解析 → 选清晰度 → 下载」核心闭环并完成基础二次元视觉；本阶段对照参考站 2019.makemepulse.com 补齐「电影感」手法，映射到二次元风格。

| 编号 | 手法 | 二次元等价 | 说明 |
| --- | --- | --- | --- |
| V1 | 蒙版揭幕 + 虹膜转场 | 魔法阵传送门收放 + 标题逐字揭开 | 场景切换如「翻页」 |
| V2 | 几何画框 | 四角画面边框 | 界面如「漫画分格」 |
| V3 | 章节台词 | 底部叙事字幕 | 每阶段一句台词，串起叙事 |
| V4 | 自定义光标 | 光标随场景变样（解析=圈圈 / 完成=比心） | 强化「进入世界」感 |
| V5 | 分段分层按钮 | 主按钮三段逐段点亮 | 关键交互的「电影感」 |
| V6 | 缠绕式进度 | 魔法符文 / 星光轨迹进度 | 替代普通横条 |

**阶段原则（约束所有视觉升级）**

1. **核心流程优先**：每一处视觉升级都必须先保证「解析 → 选清晰度 → 下载」端到端可运行、可验证；视觉是叠加层，绝不阻塞下载。
2. **预留扩展**：台词 / 转场 / 光标 / 进度全部配置外置、数据驱动；后续扩展（新场景、新错误、视频总结/字幕翻译的台词注入、主题切换）改配置不改代码。
3. **避免过度设计**：不做 v1 用不到的抽象；但核心逻辑不写死，避免后续大重构。

> 详细实现见 `docs/superpowers/plans/2026-09-22-phase2-cinematic-visual.md`；架构见 `docs/design.md §13`。
